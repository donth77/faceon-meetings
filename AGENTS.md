# FaceOn: guide for coding agents

FaceOn is a free, open-source (MIT), browser-based video meeting app that should feel instantly familiar to anyone who has used Zoom or Google Meet.

## Commands

| Command                                                       | Use                                                                                                                   |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `pnpm dev`                                                    | Dev server on http://localhost:3000                                                                                   |
| `pnpm build`                                                  | Production build (also what Vercel runs)                                                                              |
| `pnpm lint` / `pnpm typecheck` / `pnpm test`                  | ESLint / route types + `tsc` / Vitest; all three run in CI                                                            |
| `pnpm format`                                                 | Prettier (with the Tailwind class-sorting plugin)                                                                     |
| `pnpm stream:setup` / `stream:check` / `stream:lockdown-test` | Configure Stream (call type, grants, system user), report drift, prove the permission boundary. They use `.env.local` |

Node.js 24 and pnpm 10. Deploys happen by pushing to GitHub (Vercel's Git integration), never with `vercel deploy`.

## Architecture map

- `src/app/`: routes (App Router). Metadata files (`icon.svg`, `favicon.ico`, `apple-icon.png`, `opengraph-image.png`) live here. `[locale]/j/[code]` is the meeting page; `api/meetings/[code]/{join,token,end}` is the meeting API.
- `src/lib/`: server and shared logic.
  - `env.ts` (public) and `server-env.ts` (server-only) validate environment variables with Zod.
  - `auth/`: Better Auth (`server.ts`, `client.ts`, `session.ts`), password rules and error mapping. Email accounts must verify their address; responses never reveal whether an email has an account.
  - `email/`: account emails through Resend (`send.ts`; in development they print to the server log) and their localized templates.
  - `guest-session.ts`: the signed guest cookie (a random guest ID and avatar, no personal data). `rate-limit.ts`: fixed-window counters for failed attempts, keyed by a hash of the IP address, never the raw address.
  - `db/`: Drizzle schema (`auth-schema.ts` is generated by Better Auth; `meetings-schema.ts` is ours). Migrations live in `drizzle/`.
  - `meetings/`: meeting IDs and passcodes, the join rules (`rules.ts`, pure and unit-tested), the join flow (`join.ts`), queries, the API's request/response types (`api.ts`, shared with the client) and server actions.
  - `media/`: the media-provider interface (`types.ts`) and the provider registry (`index.ts`). `stream/` is the Stream adapter; a LiveKit adapter will sit beside it.
  - `device/`: browser device helpers (permission problems, remembered devices, test sound).
- `src/components/auth/`: sign-in, sign-up, verification and password-reset screens. `marketing/` holds the public header (one layout for every signed-out page), footer and language menu; `help/` the Help page; `shortcuts/` the Keyboard shortcuts dialog (`?` anywhere).
- `src/components/meeting/`: the meeting client, loaded only in the browser.
  - `meeting-entry.tsx`: pre-join → waiting for the host → room → left.
  - `media.tsx`: the client media port (`useRoomMedia()`, `<TrackView>`); `room/` is our UI on top of it.
  - `providers/stream/`: the Stream bindings. Rooms load their provider's bindings on demand.
- `public/brand/`: logo files; `public/icons/`: PWA icons.

## Conventions

- **TypeScript strict.** Validate every boundary (env, request bodies, webhooks, custom events) with Zod.
- **Secrets stay on the server.** Only `NEXT_PUBLIC_*` values may reach the browser. Server modules that read secrets import `server-only`.
- **Media SDKs only in adapter folders.** `@stream-io/*` and `livekit-*` may only be imported inside the media adapter folders. UI code talks to the provider-neutral interface.
- **UI text.** Every user-facing string comes from the message files (English first, then es, pt-BR, fr, de, ja), including `aria-label`s, tooltips and screen-reader announcements. Format dates, times and numbers with `Intl`.
- **Familiar words.** Use the words Zoom and Meet users know: Mute / Unmute, Start video / Stop video, Share screen / Stop sharing, Participants, Chat, Raise hand / Lower hand, Waiting room, Admit, Leave meeting, End meeting for all, Meeting ID, Passcode.
- **Icons.** Lucide first; another open-licensed set in the same style only when Lucide has no fit.
- **Accessibility.** WCAG 2.2 AA in light and dark themes: real buttons with labels, visible focus, keyboard access, and tooltips that also appear on focus.

## Definition of done

- Typed, with no `any` leaks.
- A unit and/or E2E test is added.
- Works at 375 px and 1440 px.
- Keyboard accessible, with visible focus, in light and dark themes.
- All UI text comes from the message files.
- No console errors.
- README, AGENTS.md and `.env.example` are updated when behavior or configuration changes.
