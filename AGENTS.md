# FaceOn: guide for coding agents

FaceOn is a free, open-source (MIT), browser-based video meeting app that should feel instantly familiar to anyone who has used Zoom or Google Meet.

## Commands

| Command                                                       | Use                                                                                                                   |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `pnpm dev`                                                    | Dev server on http://localhost:3000                                                                                   |
| `pnpm build`                                                  | Production build (also what Vercel runs)                                                                              |
| `pnpm lint` / `pnpm typecheck` / `pnpm test`                  | ESLint / route types + `tsc` / Vitest; all three run in CI                                                            |
| `pnpm format`                                                 | Prettier (with the Tailwind class-sorting plugin)                                                                     |
| `pnpm stream:setup` / `stream:check` / `stream:lockdown-test` | Configure Stream (call type, grants, system user), report drift, prove the permission boundary. They use `.env.local` |

Node.js 24 and pnpm 10. Deploys happen by pushing to GitHub (Vercel's Git integration), never with `vercel deploy`. Setting up a copy of your own (accounts, environment variables, migrations, Stream, domains) is in `DEPLOY.md`.

## Architecture map

- `src/app/`: routes (App Router). Metadata files (`icon.svg`, `favicon.ico`, `apple-icon.png`, `opengraph-image.png`) live here, with the web app manifest (`manifest.ts`) and the page the service worker shows offline (`offline.html/route.ts`, self-contained because the worker keeps a copy). `[locale]/j/[code]` is the meeting page; `api/meetings/[code]/` holds the meeting API: the ID lookup itself (GET, so the Join field can say there's no such meeting without leaving the page; it counts misses like the meeting page), `join`, `token`, `end`, `hand`, `moderate` (host controls), `notes` (AI notes on or off, for hosts, where the meeting's host allows them), `notes/[sessionId]` (save, share or delete a session's AI notes), `lobby` (the waiting room, for hosts), `admission/[requestId]` (asking to join) and `seen` (the meeting page says when someone leaves, so a session nobody's in ends then, not when it's next noticed). `api/integrations/google-calendar` disconnects Google Calendar (`DELETE`).
- `src/lib/`: server and shared logic.
  - `hosting/`: who hosts full meetings beyond the operator's settings. The admins' list of approved addresses (`allowlist.ts`), requests to host full meetings and their answers (`requests.ts`), the plan with both counted (`access.ts`, `hostingPlanOf`), the emails about them (`emails.ts`), and the pure rules (`rules.ts`). `/admin` (`app/[locale]/(app)/admin`, `components/admin/`) is for admins only and does nothing else: each action in `admin-actions.ts` checks the caller is an admin, and none can change, delete or see into an account.
  - `env.ts` (public) and `server-env.ts` (server-only) validate environment variables with Zod.
  - `auth/`: Better Auth (`server.ts`, `client.ts`, `session.ts`), the origins sign-in trusts (`origins.ts`: production, the deployment's own address, never a wildcard), password rules and error mapping. Email accounts must verify their address; responses never reveal whether an email has an account.
  - `email/`: account emails through Resend (`send.ts`; in development they print to the server log) and their localized templates.
  - `guest-session.ts`: the signed guest cookie (a random guest ID and avatar, no personal data). `rate-limit.ts`: fixed-window counters for failed attempts, keyed by a hash of the IP address, never the raw address. `log.ts`: errors for the server log without a failed query's values. `uuid.ts`: IDs from URLs are checked before any query.
  - `db/`: the database client (`index.ts`), waking a sleeping database as someone shows intent (`wake.ts`, `wake-rule.ts`; the page side is `components/app-shell/wake-on-intent.tsx`, the route `/api/wake`), and the Drizzle schema (`auth-schema.ts` is generated by Better Auth; `meetings-schema.ts` is ours). Migrations live in `drizzle/`.
  - `meetings/`: meeting IDs and passcodes, and reading what someone typed or pasted into the Join field (`codes.ts`), the join and moderation rules (`rules.ts`, pure and unit-tested: who gets in, and the host-controls permission matrix), the join flow (`join.ts`), admitting someone (`admission.ts`, the only place media tokens are minted), the waiting room (`waiting-room.ts`), host controls (`moderation.ts`), AI notes on and off, including meetings that start them automatically (`notes.ts`), saved AI notes and who may read them (`saved-notes.ts`), the session's shared state (`session-state.ts`: hands, roles, spotlight, policies and whether AI notes are on (or were stopped), written under a per-session lock), session lifecycle (`sessions.ts`), the hosting policy (`hosting.ts`: approved hosts get full limits, everyone else demos; `isAdmin` is `ADMIN_EMAILS` only), how long records are kept (`retention.ts`, as the privacy policy says) and the housekeeping sweep that enforces it (`sweep.ts`, run daily by Vercel Cron at `/api/cron/sweep`), Previous (`history.ts`, with who came worked out in `attendees.ts`), queries, the API's request/response types (`api.ts`, shared with the client) and server actions (the schedule form's signed draft is made in `schedule-draft.ts`, which is server-only, never an action).
  - `media/`: the media-provider interface (`types.ts`, including `CameraProcessor` and `MicrophoneProcessor`, which a provider's client runs on the camera or the microphone before anything is sent) and the provider registry (`index.ts`). `stream/` is the Stream adapter (its webhook is parsed in `webhook.ts`); a LiveKit adapter will sit beside it. Hosts' browsers get the same Stream grants as everyone's: host controls go through our API (`scripts/setup-stream.ts`, proven by `stream:lockdown-test`).
  - `device/`: browser device helpers (permission problems, remembered devices, test sound).
  - `notes/`: AI notes, made in the browser: speech to text on each person's own device (`speech.ts`), the notetaker's transcript and notes (`transcript.ts`, kept only in that tab), the notes' shape, prompts and Markdown (`notes.ts`), making them on-device or with the host's own key (`engines.ts`, `providers.ts`: the five providers, called straight from the browser) and Settings → AI notes (`settings.ts`). Whether a host's meetings offer AI notes at all is an account setting, off to start (`user.ai_notes`, `allowNotesInMeetings` in `lib/meetings/notes.ts`), copied into each open session so co-hosts are held to it too.
  - `ai/`: Chrome's built-in model through the Prompt API (`built-in.ts`), shared by Help's assistant and AI notes.
  - `effects/`: backgrounds and effects, processed on the device: the choices and how they're stored (`effects.ts`), the engine (`engine/`: MediaPipe's selfie segmenter finds the person, a guided filter lines the mask's coarse edges up with the camera image, and a WebGL2 compositor draws the blur, picture or video behind them; it loads only when a camera has an effect), the processor the room hands to the media provider (`camera-effects.ts`), and backgrounds people add, kept in their browser (`uploads.ts`). Nobody receives the camera unprocessed while an effect is on: if one can't run, the video goes off.
  - `google-calendar/`: Google Calendar sync, for hosts who connect it in Settings → Calendar (Better Auth's `linkSocial` adds the `calendar.events.owned` scope; sign-in never asks for it). The scope and shared types (`shared.ts`), where someone's connection stands, their access token (refreshed by Better Auth; `refresh.ts` notices when Google refuses the grant, which means reconnecting) and disconnecting (`connection.ts`), the Calendar API client (`api.ts`), the events a meeting should have (`events.ts`: one per one-off meeting or series rule, with one-off changes as changed or cancelled occurrences), and the sync that brings the host's calendar in line after each save (`sync.ts`, `reconcile.ts`). A synced meeting keeps its event IDs in `meeting.google_events`; Google emails the invitees.
  - `noise/`: noise suppression on the microphone (Settings → Audio): off, standard (the browser's own) or strong, the default: RNNoise in an AudioWorklet on the device (`engine.ts`, loaded only when a microphone needs it), handed to the media provider as a `MicrophoneProcessor` (`microphone-noise.ts`). Where strong can't run, or stops working, the browser's own takes over and people are told once (`support.ts`).
  - `preferences.ts`: Settings kept on this device (time format and zone, noise suppression, mirroring, HD, single-key shortcuts…) and `useIntlLocale()`, the locale every date and time is formatted with. `withDefaults()` gives settings as they act (with Notifications off, every sound, pop-up and reminder is off); `chosenSettings()` gives them as chosen, for Settings to show.
- `src/components/auth/`: sign-in, sign-up, verification and password-reset screens. `marketing/` holds the public header (one layout for every signed-out page), footer and language menu; `help/` the Help pages; `settings/` the Settings sections (also shown in the meeting's Settings dialog); `notes/` the AI notes view, the flow that makes and saves them (in the meeting's panel and after leaving) and the saved notes page (`/previous/<session>/notes`); `shortcuts/` the Keyboard shortcuts dialog (`?` anywhere) and the list it shares with Settings → Accessibility; `effects/` the backgrounds and effects picker with its live preview (pre-join, the meeting's panel, Settings); `device/` what pre-join, Settings and the meeting share about your camera and microphone (the mirrored preview, the local track, the mic meter, the problem note and the Audio and Video switches); `google-calendar/` connecting Google Calendar from a form (in a consent window that reports back), the schedule form's "Add to my Google Calendar" row, and what Google Calendar did after a save, with Retry or Reconnect.
- `src/components/meeting/`: the meeting client, loaded only in the browser.
  - `meeting-entry.tsx`: pre-join → waiting for the host, or asking to join → room → left.
  - `media.tsx`: the client media port (`useRoomMedia()`, `<TrackView>`); `room/` is our UI on top of it. Voices change many times a second, so they aren't in the participant list: `useSpeaking`, `useAudioLevel` and `useDominantSpeakerKey` let just the component that shows one follow it, and adapters keep room media the same object until something it shows changes (`lib/reuse.ts`). Roles and policies come from the session's shared state (`room/roles.ts`); host actions call our API, never the media SDK, and the ⋯ menu offers what `canModerate` (`lib/meetings/rules.ts`, shared with the server) allows.
  - `room/meeting-shell.tsx` lays the room out; its parts live in hooks beside it: `use-panels.ts` (side panels, and where focus goes as they open and close), `use-meeting-notes.ts`, `use-reactions.ts`, `use-hands.ts`, `use-screen-share.ts` and `use-room-alerts.ts`.
  - `providers/stream/`: the Stream bindings. Rooms load their provider's bindings on demand.
- `content/help/<locale>/`: the Help articles, one Markdown file each with front matter (`title`, `summary`, `category`, `order`). Write `{appName}` for the app's name. A language without its own folder shows English. `src/lib/help/` reads them; `/help` lists and searches them, and `/help/<file name>` shows one.
- `content/legal/`: the privacy policy, the terms and the credits (`/privacy`, `/terms`, `/credits`), in Markdown with front matter (`title`, `updated`). The credits name everyone whose work FaceOn uses (avatars, backgrounds, the segmentation model, fonts and icons); a unit test checks every background's maker is there, so add a line when a background or credited asset is added. `src/lib/content/legal.ts` fills in `{appName}`, `{siteUrl}`, `{operator}`, `{contact}` and `{governingLaw}` from the operator settings in `.env.example`, so a self-hosted copy names itself. Keep them true to what the code does: when a feature changes what's kept or who handles it, update the privacy policy and its `updated` date. Sign-up, sign-in and a guest's pre-join link to both (`components/legal/`).
- `public/sw.js`: the service worker (registered in production by `src/components/pwa/service-worker.tsx`). It caches build files, icons and backgrounds, and shows the offline page; it never caches pages, `/api`, media or other sites. Its rules (`cacheRule`) are tested in `src/lib/pwa/service-worker.test.ts`. Installing as an app is `src/lib/pwa/install.ts` (how this browser can, and Chrome's prompt) with its buttons and hints in `src/components/pwa/install-app.tsx` (Settings → General, the account menu, and a one-time card on Home on phones).
- `public/brand/`: logo files; `public/icons/`: PWA icons; `public/backgrounds/`: the default backgrounds, credited in `CREDITS.md` (the abstract ones are drawn by `scripts/backgrounds.ts`; the moving ones, in `motion/`, are looping public-domain and CC0 footage); `public/effects/`: the segmentation model, and MediaPipe's Wasm runtime, which `scripts/effects-assets.ts` copies there before `dev` and `build`; `public/noise/`: RNNoise's worklet and Wasm, which `scripts/noise-assets.ts` copies there the same way (notices in `CREDITS.md`).

## Conventions

- **TypeScript strict.** Validate every boundary (env, request bodies, webhooks, custom events) with Zod.
- **Secrets stay on the server.** Only `NEXT_PUBLIC_*` values may reach the browser. Server modules that read secrets import `server-only`.
- **Hosts' AI keys never reach our server.** They're kept in the host's browser and sent only to their AI provider; no route accepts, stores or logs them.
- **Media SDKs only in adapter folders.** `@stream-io/*` and `livekit-*` may only be imported inside the media adapter folders. UI code talks to the provider-neutral interface.
- **UI text.** Every user-facing string comes from the message files, including `aria-label`s, tooltips and screen-reader announcements: English first; es, pt-BR, fr, de and ja follow. Format dates, times and numbers with `Intl`; `lib/time.ts` has the shared helpers (days, time ranges that cross midnight, lengths of time such as "1 hr, 15 min").
- **Familiar words.** Use the words Zoom and Meet users know: Mute / Unmute, Start video / Stop video, Share screen / Stop sharing, Participants, Chat, Raise hand / Lower hand, Waiting room, Admit, Leave meeting, End meeting for all, Meeting ID, Passcode.
- **Icons.** Lucide first; another open-licensed set in the same style only when Lucide has no fit.
- **Accessibility.** WCAG 2.2 AA in light and dark themes: real buttons with labels, visible focus (the `focus-ring` utilities), keyboard access, and tooltips that also appear on focus. When a control removes itself or a screen changes, move focus somewhere sensible first.
- **React Compiler.** It's on (`reactCompiler` in next.config.ts), so components and values are memoized for you: write plain code, and reach for `useMemo` or `useCallback` only where an effect or an external store needs a stable identity. It assumes module-level variables never change, so a function that changes one belongs at module level, outside any component or hook (see `lib/pwa/install.ts`).

## Definition of done

- Typed, with no `any` leaks.
- A unit and/or E2E test is added.
- Works at 375 px and 1440 px.
- Keyboard accessible, with visible focus, in light and dark themes.
- All UI text comes from the message files.
- No console errors.
- README, DEPLOY.md, AGENTS.md and `.env.example` are updated when behavior or configuration changes.
